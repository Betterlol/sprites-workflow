# 视觉检查与验收

以当前任务目标、已采用的角色基准和动作意图判断结果。单帧比较用于定位形状和偏移，连续播放用于判断运动；检查范围随本次改动确定，不要求固定截图或报告包。

## 单帧与角色一致性

| 检查点 | 判断方式 |
| --- | --- |
| 轮廓与结构 | 关键姿态清楚，肢体、五官、服饰和道具没有不合理的增减、连接或变形 |
| 身份与画风 | 对照基准和邻帧的比例、配色、视角、线条与材质，区分动作变形与角色设计漂移 |
| 透明与裁切 | 在浅色、深色或棋盘背景上检查白边、黑边、背景残留、杂点、半透明损失及被截断的内容 |
| 尺度与位置 | 在同一画布尺度比较身体、重心与接触点，避免自动适应预览掩盖大小闪变 |
| 实际尺寸可读性 | 在目标使用尺寸确认姿态与重要细节可辨认，放大只用于定位问题 |

并排图适合看整体差异，叠图适合定位偏移，放大图适合查边缘；任何一种静态材料都不能单独证明动画流畅。

## 连续播放、循环与衔接

先按目标顺序和实际时长正常播放，再慢放或逐帧定位问题。慢放流畅不代表正常速度可读；单帧好看不代表运动连续。

| 检查点 | 需要辨别的现象 |
| --- | --- |
| 动作意图 | 发力方向、接触与恢复能看懂，关键姿态没有被过快略过或无故停留 |
| 连续性 | 位置、轮廓、体积、遮挡和道具轨迹无非预期跳变，细节没有闪烁 |
| 接触关系 | 应固定的接触点不滑动，离地与落地可信；腾空或有意位移按动作判断 |
| 节奏 | 停留、重复与加减速服务于意图，没有因漏帧、重复帧或时长设置造成卡顿 |
| 循环接缝 | 连播数轮查看尾到首的位置、姿态、运动趋势与停留；首尾同图也可能顿挫 |
| 片段连接 | 检查前段尾部、过渡和后段头部，并按真实编排播放完整动作与实际前后动作 |

多个允许入口、中断位置或终止状态分别检查实际会发生的边界。局部片段不能表达最终节奏时，直接检查完整动作的对应范围。一次性动作不强制闭环，有意夸张、顿帧和拖影按目标风格判断。

## 检查交付版本

核对素材版本、帧顺序、逐步时长与播放模式，游戏结果检查 `runtime`，展示结果另查 `display`。人工修图、外部修改和未保存草稿要明确采用哪一份，不把旧预览当成新结果。

涉及导出时实际查看导出的图片和动画，检查透明、尺寸、顺序、节奏及编码变化。QA 报告用于精确核对引用和毫秒时长；GIF 取整或相同画面合帧不能直接当作制作漏帧，也不能凭报告生成就宣布视觉通过。

基准、图片、处理或编排改变后，复查受影响的子动作、共享引用、两侧接缝及完整动作，重新建立对应版本的结论。

## 形成结论

把问题定位到帧或边界，例如“末帧回首帧时头部向右跳动”，再根据原因选择修原画、切割、处理或时序。避免仅写“有点怪”，也不在未定位原因时要求重做整段。

交付简述成果位置、主要变化、实际检查方式和范围，以及仍影响使用的问题。只能查看静态图时，连续播放列为待验收；只有本地工具结果时，游戏内表现不宣称通过。已有采用记录直接引用，需要新增的来源映射与版本结论简短补充即可。
