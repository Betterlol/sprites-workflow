# Sprites 工作指导

本目录指导 Agent 如何推进精灵图与动画任务，以及如何判断成果质量。项目结构、功能和命令见[项目文档](../../README.md)，不在这里重复。

## 按任务使用

- [工作方法](workflow.md)：新建动画、扩展已有动作或修复局部问题时阅读，按实际任务选择步骤。
- [视觉检查](visual-review.md)：试作后、定位质量问题以及交付前使用，检查范围随改动确定。
- [制作与操作 skill](../skills/sprite-workflow/SKILL.md)：需要分段与过渡技巧，或把导入、处理、编排、核对和交付串成具体操作时使用。

## 共同原则

1. **以本次目标为范围。** 明确目标角色、动作或片段，以及用户期待的交付结果。已有明确要求直接执行；会改变制作方向的信息缺失时才询问。
2. **先看现有成果。** 阅读相关工程说明，实际查看参考图、已有单帧和动画。区分用户明确要求、既有成果体现的约定，以及自己尚待验证的推断。
3. **延续已有授权。** 在授权范围内完成制作、修正和检查，不逐步重复请求确认。扩大动作集合、改变角色设计或替换既有成果等决定，以用户授权为依据。
4. **保留已有工作。** 修改前识别原图、人工修图、未保存编辑和其他人的改动。通过项目支持的操作提交结果，不绕过版本冲突与引用保护；不顺手清理无关素材。
5. **先解决具体问题。** 能通过局部修图、切割、对齐或时长调整解决的问题，先做局部修正。方向未经验证时，先试少量代表帧，再决定是否批量展开。
6. **按实际证据报告。** 文件生成、程序检查和视觉检查分别说明。检查方式服从用户本次要求，未查看或无法验证的部分明确列出。

工作记录以足够继续制作和定位问题为度，不要求固定模板、逐步截图或每次新增报告。已有参考和决定可以直接引用，无需重复抄写。

## 制作时的保障

- 生成与修图实际向工具提供采用的基准、问题帧和必要邻帧或端点；工具输入受限时说明限制。
- 边界取最终运行时编排的真实帧与时长。修改编排后核对完整组成，展示播放另查；改变共享素材或子动作后，复查受影响的引用及前后衔接。
- 采纳原画保留 source 来源，人工修图与独立变体保留采用图片及来源映射。简记编排取舍与检查版本，修改相关内容后重新建立验收结论。
