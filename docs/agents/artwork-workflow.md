# Agent 动画制作流程

制作任务按以下流程完成；已有基准和记录直接沿用，不重复请求确认。CLI 参数按需查 [工程操作](../reference/project-operations.md)，复杂动作可选用 [制作技巧](../reference/animation-techniques.md)。

## 1. 核对工程与基准

读取目标工程 README、pipeline.json，用 `projects.py status <工程ID>` 核对实际素材与引用。说明过期时先标出差异，不凭旧名称或文件编号猜测。

实际查看已确认 Idle 的精确图片与版本，沿用角色朝向、比例、画风、视觉尺度、配色和接地点，不自行替换基准。后续生成实际提供该图片及必要边界图片，不能只写路径。没有明确基准时先列出待确认项，不批量制作正式后续动作。

## 2. 长动作先拆分，生成时约束边界

长动作必须按语义拆成可独立播放的子动作，每段生成完整 spritesheet，完整动作引用这些子动作。动画 Idle 也使用 sheet。

- 先确定各段入口、出口、节奏与状态。边界取最终 runtime 编排的真实帧，记录其引用与播放位置；嵌套时注明槽位路径。不得用原图格子顺序、最大文件编号或展示动画端点替代。
- 后段生成时实际提供前段已采用的末帧，约束其首姿态。只有姿态、运动和状态都连续时才能直接接上；共享边界通常只播放一次，有意停顿要明确。
- 无法直接接上时，同时提供两个已采用端点、Idle 和附近运动帧，生成整张过渡 sheet。完整编排保留原端点，选择过渡内部帧，检查两侧接缝；失败则重做或重新拆分，不用散落的独立帧拼出运动。
- 单帧生成可用于具体坏帧修复，或规划复杂衔接的中间关键姿态，后者见制作技巧。关键姿态之间仍生成完整 sheet。

坏帧修复必须实际提供 Idle、坏帧和相邻帧，明确替换的引用与缺陷；采纳后先导入 source 再处理，替换后检查前后两侧与完整动作。缺少一段运动时生成过渡 sheet，不以修复名义逐张补齐。参考不足或工具无法接收必要图片时，说明限制，不声称已满足端点约束。

## 3. 导入、切割与调整

候选放 `_work/<task>/`，正式 references 只保留用户参考、一个已确认 Idle 基准和必要最终记录。采纳的原画先用 `projects.py import --kind source` 导入，再保存切割或 apply；单帧修复、采用为播放素材的关键姿态和可玩的 Idle 原图同样保留 source 来源。参考图不参与切割，旧 reference 继续兼容。

切割后核对区域与稳定帧 ID；按需调整整组或单帧缩放、偏移。fit_height 按单张原图完整轮廓计算，不能保证跨 sheet 身体同尺度；道具、头饰和特效会影响轮廓，轮廓底边也不等于脚底。对照角色本体校正，保留蹲伏、跳跃等合理变化，避免逐帧拉成同高或强行压到地面。单帧校正应有依据，并检查是否引入缩放抖动。

保存参数不等于应用图片，review 使用已应用的 processed。新处理结果保留在 source 派生目录，imports 与 _approved 仅作历史兼容；不直接覆盖正式 PNG 来绕过来源。目录细节见 [工作目录](work-directory.md)。

## 4. 组装与 review

动作与序列均可引用单帧、动作或其他序列；明确范围、重复、调速和停留，保留实际逐帧时长。不要通过重命名素材改变动作顺序。引用子动作会随其更新，旧平铺 sprites 不会自动建立这种关系。

完整动作必须与计划采用的子动作组成核对：逐步引用、顺序、步数、每步时长和总时长一致；范围截取、边界去重、重复或停顿的差异须有明确依据，不得静默漏掉过渡。优先用 `check-composition` 对比；工具无法表达时直接比较展开记录，不能省略核对。

review 必须覆盖以下适用范围：

- 每个子动作；循环子动作还要检查自身首尾。
- 每处接缝的前段尾部、过渡和后段头部；过渡两侧都检查。
- 完整动作，以及实际会发生的“前置动作 → 完整动作 → 后置动作”。核对真实 Idle 离开 / 返回帧，多个允许入口或中断位置分别检查；终止动作检查最终状态。

局部与完整 review 使用相同的 runtime 边界、去重、重复和逐步时长。局部片段无法表达最终节奏时，直接检查最终动作对应范围。区分观察用循环与游戏中真实发生的接缝，展示编排不能代替游戏验收。工作台 Idle 叠图取 idle 展开首帧，不自动绑定正式参考。

用 `qa` 生成动画、对照图和报告，按正常速度、慢放和逐帧检查；保持固定画布，用地面线、前帧叠图和正式 Idle 对照，不用插值或淡化掩盖问题。检查要点：

- 身份、头身比例、画风、配色和身体尺度一致，无无意放大缩小。
- 接地点、重心和离地轨迹合理，无非预期滑动、跳动或瞬移。
- 接缝方向、速度与节奏连续，无遗漏运动、突停、反跳或无意重复。
- 表情、左右手持握、遮挡、道具数量及内容状态连续。

失败时按原因返工：对齐问题调处理参数；结构、表情或道具画错则返工原画；运动缺失或接缝不自然则重做过渡或重新拆分；编排错误则修正范围与时长并同步 review。不要用缩放偏移补救结构错误，也不要用降 FPS、跳帧或无依据重复掩盖问题。

交付包按需用 `check-export` 核对正式图片与 runtime 时序，独立展示编排另行核对。只有适用检查通过且记录对应当前配置与素材版本，才可宣布验收通过；端点相似、配置合法、报告生成或导出成功都不能代替视觉检查。

用户自行验收或当前环境无法查看播放时，交付结果并标明待验收，不虚报通过。基准、原画、处理或时序变化会使相关结论失效，重查受影响子动作、两侧接缝及完整动作；旧成果退出活动使用前保留可追溯版本。

## 最少记录

只在工程 README 补充本次新增或变化的信息：采用的基准与原画来源、实际边界与编排取舍、检查版本及通过 / 待验收项。格式自由，已有内容不重复抄写；只有需要复查时才保留关键证据，无需为每帧截图或填写长表格。
