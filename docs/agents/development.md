# 开发与文档 Agent

面向修改代码、文档或排查问题的 Agent。共享开发入口见 [开发与维护](../development/contributing.md)，依赖关系见 [架构](../development/architecture.md)。

## 开始与执行

1. 确认本次任务、用户的测试限制、工作树已有改动，以及适用的 AGENTS 规则。保留用户未提交工作和无关工程。
2. 根据任务阅读对应实现与当前参考文档。排查网页问题先核对实际模型、保存边界与调用链；不要通过试改真实素材来定位程序问题。
3. 将领域规则留在 domain、图像计算留在 imaging、磁盘与版本留在 storage，应用操作协调事务，HTTP 与 CLI 只转换输入输出。新业务代码使用正式子包，避免依赖兼容入口。
4. 保留 v2 配置、旧资源适配、稳定帧与槽位身份、版本检查和引用保护。未来 .meta 需要显式设计迁移、跨文件版本与事务，不能顺带拆分用户配置。
5. 按获准范围验证并报告证据。默认代码检查命令见开发指南；用户禁止实际测试时不运行测试或浏览器，列出未执行项。

## 文档任务

- 文档职责与正式路径由 [文档目录](../README.md) 定义。用户操作、Agent 规范、共享契约和历史记录分别维护，用链接引用，避免复制完整流程。
- 以当前源码核对当前行为，历史方案不作为已实现依据。保留历史测试记录所属的版本与语境，不把它挪成当前验证结果。
- 不修改现有 artwork、pipeline.json，不导入、处理、迁移、删除或整理工程素材。不为核对文案运行制作流水线。
- 移动文档时检查相对链接；旧公共入口保留迁移页。仅做文档修改时，检查链接、格式与变更范围即可，不要求运行 Python/Node/浏览器功能测试。

## 交付说明

说明改了什么、影响范围、执行过的检查和待确认项。区分源码检查、静态检查、自动化测试、浏览器交互测试与美术视觉验收；一种证据不能替代另一种。用户自行体验的阶段交付应给出具体体验范围，而不是伪造验收结果。
