# Agent 制作任务与生成提示词示例

使用前填写实际工程、参考路径和需求。这是任务模板，不能只把文件名发给图像生成工具；必须实际提供相关图片。完整约束见 [制作与验收流程](agent-sprite-workflow.md)。

## 给 Agent 的任务

为 2D 动作游戏制作角色 `<角色>` 的 `<目标动作>`，工程为 `workspaces/<project-id>/`。先读取 AGENTS、工作区说明、制作流程、目标工程 README 和当前配置，并用 `tools/projects.py status <project-id>` 核对现状。

沿用工程已确认的 IDLE 基准 `<参考路径>` 与角色尺度、配色、朝向和接地点。没有已确认基准时先明确候选与待确认项，不批量制作正式后续动作。若从零开始，动作需求可包括 idle、run、jump、land、dash、attack、hurt、die、attack_special；按当前任务范围逐项制作。

先列出子动作语义、入口 / 出口状态、运行 FPS 和时长，再生成每段完整 spritesheet。后段以实际采用的前段末帧约束起点；能直接共享时去重，不能自然衔接时用前后实际端点生成整张过渡 sheet。单帧生成仅用于明确坏帧修复。

候选保存在 `_work/<task>/`；采纳的原画先通过管理 CLI 导入 source 再处理。按同一份范围、重复与停顿记录编排子动作、接缝 Review 和最终完整动作，核对引用与时长，然后以正常运行速度、慢放和逐帧方式检查。记录参考来源、端点槽位与引用、选帧取舍、所用版本和实际验收结果；存在未检查项时标为待验收。

## 给图像生成工具的过渡要求

提交前实际附上：已确认 IDLE、前段出口 E、后段入口 S，以及边界附近的运动上下文，并注明各图用途。以下占位内容均须替换：

```text
制作 <角色> 的 <子动作 A> 到 <子动作 B> 的完整过渡 spritesheet。

形象参考：附图 IDLE，保持头身比例、配色、线条、朝向和本体视觉尺度。
起点：附图 E，来自 <动作 A / 运行时槽位 / processed 引用>。
终点：附图 S，来自 <动作 B / 运行时槽位 / processed 引用>。
运动上下文：附图 <前段尾部、后段头部>，用于保持运动方向与速度连续。

布局：<行列、阅读顺序、透明背景、帧间留白>。
节奏：目标 <FPS>，过渡约 <时长>，生成 <帧数> 帧，包含首尾约束姿态。
动作：<起点状态 → 渐进过程 → 终点状态，身体和道具的运动路径>。
状态：<左右手、持握、表情、道具数量、内容变化和遮挡关系>。
空间：<角色本体大小、站立接地点或合理离地轨迹>，不要逐帧自动拉齐总轮廓高度。

首姿态匹配 E，末姿态匹配 S，中间帧完成运动，不在最后一帧突然切换。
```

切图处理后检查 `原 E → 首个中间帧` 和 `最后中间帧 → 原 S`。默认只采用过渡的中间帧，完整动作保留原端点；实际采用多少中间帧由运动与时长决定，不固定为两帧。生成成功不代表已经通过验收。
