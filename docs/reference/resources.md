# 资源组合与播放（共享参考）

面向需要理解编排语义的用户、Agent 和开发者。界面步骤见 [网页指南](../users/workbench.md)。资源仍保存在 pipeline.json v2，没有引入 .meta。

## 资源与槽位

单帧、动作、衔接序列都是可引用资源。动作保留游戏交付用途，序列保留衔接检查用途；二者共用槽位，可以任意嵌套，组合不复制或重新处理 PNG。

```json
{
  "slots": [
    {"id": "begin", "resource": {"kind": "action", "ref": "windup"}},
    {"id": "pose", "resource": {"kind": "sprite", "ref": "attack/003.png"}, "duration_ms": 80},
    {"id": "return", "resource": {"kind": "sequence", "ref": "return_to_idle"}, "repeat": 2, "speed": 1.2}
  ]
}
```

这是动作或序列对象内的字段片段，不是一份可直接保存的完整工程配置。kind 区分 sprite、action、sequence；sprite ref 相对于 processed_sprites，其他 ref 是各自集合的 ID。

槽位有资源内独立 ID，引用同一资源两次仍是两个槽位。槽位 ID 与原图的稳定帧 ID 是不同层次的身份。网页重命名动作会更新对应引用，不能绕过操作随意重命名文件。

## 时间与范围

| 设置 | 规则 |
| --- | --- |
| 单帧默认时长 | 使用当前资源 FPS；duration_ms 可覆盖该 sprite 槽位停留 |
| 复合资源时长 | 继承子资源逐步时长，不强制统一为根 FPS |
| repeat | 显式有限重复，1–100；子资源顶层无限循环不在引用中无限展开 |
| speed | 本次引用调速，0.01–100，沿用毫秒取整规则 |
| start / end | 当前引用模式展开后的步编号，从 0 起，结束包含在内 |
| mode | 显式 runtime / display 覆盖当前子引用的模式 |

动作中的子引用默认 runtime；序列中的子引用默认继承当前请求模式，显式 slot mode 优先。单帧时长覆盖不用于替换整个复合片段时长，复合片段通过速度和范围控制。

**资源槽位与播放步不同**：一个 action 槽位可能展开成许多帧。接缝记录应同时指明原资源、槽位 ID / 嵌套路径、展开步编号、PNG 引用和实际毫秒时长。

共享边界不会自动去重；必须明确选择范围，停顿与重复也要显式编排。根动作默认 FPS 不能代替实际逐帧时长，引擎接入和 QA 应读取展开时序。

## 游戏播放与展示播放

日常调整与编排编辑器使用 runtime。导出设置管理 display 的 FPS、animation.order、逐步 durations_ms 或统一 duration_ms、loop；0 循环为无限。order 指向最终展开的游戏帧索引，可以重排或重复。

展示未覆盖时长时继承被引用片段的实际时长。编辑组合结构时，按来源标识重映射已有展示顺序和时长，不自动补回原先有意省略的帧；新出现的帧会追加。需要清除展示覆盖时在导出设置使用“恢复游戏播放”。

槽位高级设置中显式引用 display，是组合内容本身的选择；不表示整个编辑器切换了展示模式。游戏验收仍须核对最终 runtime 展开结果，并说明其中有意采用的子引用模式。

## 更新、追踪与保护

通过资源槽位引用子动作或序列时，子资源改动会影响所有依赖它的组合。旧的平铺 sprites 列表不会自动形成子动作链接；共享同一 PNG 的位置仍会随图片更新。

展开结果追踪逐步来源、嵌套 lineage、槽位与原始 runtime 位置，便于定位重复或跨资源帧。修改素材、参数或编排后，相关视觉验收失效；重新检查子动作、受影响接缝与完整动作。

循环引用、缺失组合、非法范围被拒绝。嵌套深度最多 32 层，最终展开最多 10,000 帧。PNG 文件存在性还由存储与工程状态检查，组合结构校验不能代替素材检查。删除保护覆盖动作与序列中的直接单帧、间接组合依赖。

## 旧格式与实现边界

旧动作 sprites、旧序列 clips 在读取时适配；编辑某个资源结构时才将该资源转换为 slots，不批量改写整个工程或生成新图片。旧适配槽位使用稳定的 frame / clip 位置身份；新槽位由编辑器生成 ID。

后端 `tools/sprite_pipeline/domain/resources.py` 负责解析、校验和来源追踪；domain.actions 保留兼容调用。前端 web/resources.js 计算草稿，web/composition.js 管理槽位交互，web/explorer.js 管理统一工作目录。预览、QA、导出与批量选择使用相同领域播放规则。

CLI `--sequence` 的临时 steps JSON 与这里的持久化 slots 不同，见 [工程操作参考](project-operations.md)。软件测试、配置校验和成功导出均不代表动作自然度已通过视觉验收。
