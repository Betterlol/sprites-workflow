# 资源组合

素材库现在包含单帧、动作和序列。动作与序列都可以引用任意一种资源，引用保留原资源的身份与处理结果。资源仍保存于当前工程的 `pipeline.json`；此轮没有引入 `.meta` 或改写已有工程。

## 网页操作

1. 进入动作编排或衔接检查，选择或新建要编辑的资源。
2. 在左侧素材库按“全部资源 / 单帧 / 动作 / 序列”筛选，点击或拖入时间轴，也可多选后一次加入。
3. 时间轴中的每张卡片是一个槽位。可拖动排序、复制、移除；右侧可更换引用，调整次数、速度、范围与单帧停留时间。
4. 点击“展开帧”查看该槽位实际播放的单帧、全局播放步编号、时长。点击具体帧可定位播放；悬停查看逐层来源。
5. 点击“编辑原资源”进入被引用的动作或序列，再通过“返回父组合”回到原处。
6. 保存工程后生效。图片仍通过切割和单帧调整页面处理；组合不复制或重新处理 PNG。

槽位参数只影响当前这一处引用。编辑原资源会同步到所有引用它的组合；已有素材仍只需改一次图片。被使用的组合不可直接删除；素材图片的删除保护同样覆盖序列中的直接引用。

动作保留游戏导出用途，序列保留衔接检查用途，两者共用槽位和展开规则。可以将一个序列加入动作再导出，也可以直接导出当前序列的播放记录与动画。

## 播放规则

- 单帧默认时长来自当前资源的 FPS；槽位可单独设置停留时间。
- 被引用的动作或序列默认只播放一遍，忽略它作为顶层播放时的无限循环。引用次数由槽位明确指定，上限 100 次。
- 片段时长沿用被引用资源；速度作用于本次引用，采用相同的毫秒取整规则。
- 槽位可选择引用游戏播放或展示播放。动作中的引用默认使用游戏播放；序列中的引用默认跟随当前序列所选模式。显式槽位设置优先。
- 范围使用所选引用播放方式展开后的步编号，起始和结束均从 0 起，结束步包含在内。修改范围不会裁掉原资源。
- 动作的展示配置作用于展开后的游戏帧，可独立保留顺序、重复和时长。编辑槽位时按来源标识重映射已有展示顺序；不会把原先有意省略的帧补回来。新出现的帧追加到展示配置。
- 展示配置未显式覆盖时长时继续继承片段时长。需要清除旧覆盖时，可点击“展示配置恢复为组合顺序”。

预览、QA、资源导出和旧批量选择都通过同一个后端展开器。导出记录保留每帧时长；图集的默认 FPS 只作为默认值，组合中不同片段的时长记录仍然保留。

## 配置与兼容

旧动作的 `sprites` 和旧序列的 `clips` 会在读取时适配。修改组合结构时才将该资源转换成 `slots`，不会批量迁移工程，也不会生成新的图片。

```json
{
  "slots": [
    {"id": "begin", "resource": {"kind": "action", "ref": "windup"}},
    {"id": "pose", "resource": {"kind": "sprite", "ref": "attack/003.png"}, "duration_ms": 80},
    {"id": "return", "resource": {"kind": "sequence", "ref": "return_to_idle"}, "repeat": 2, "speed": 1.2}
  ]
}
```

槽位有独立 ID。新槽位在网页中生成 ID；旧资源适配使用稳定的原槽位 ID。动作和序列的引用使用当前集合中的 ID，网页重命名动作时同步更新引用。素材路径继续使用已有稳定帧引用。未来配置拆分时，可在此基础上增加跨文件资源身份。

实现入口：`domain/resources.py` 负责解析、校验和来源追踪，`web/resources.js` 提供相同规则的草稿计算，`web/composition.js` 管理素材库与槽位交互。

循环引用、缺失组合、非法范围会被拒绝；嵌套深度限制为 32 层，展开结果限制为 10,000 帧。共享边界帧不会自动去重，停留和重复需要明确编排。
