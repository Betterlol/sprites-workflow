# Sprite Workbench 改进设计

## 目的

让已有的本地 Sprite 工作台在大工程中仍能快速打开、浏览和预览，并补齐可恢复的编辑流程与清晰的界面。工作流继续围绕 `pipeline.json`、原图、processed 素材、动作和 Review；网页与 `tools/projects.py` 共享同一套领域操作。

## 范围与顺序

1. **性能阶段**：减少图片请求时的配置解析和重复传输；让工程快照复用未变化图片的元数据；精简并复用切图预览；降低后台检查开销；让长序列播放和素材库只加载近期需要的图片。阶段结束后提供提交供实际工程测试。
2. **工作流阶段**：为会写入图片的操作提供明确的版本恢复；允许在网页调整工程画布和锚点并说明重处理影响；提供配置冲突的差异与选择性合并；为长任务显示真实进度并支持安全取消。
3. **界面阶段**：提高字号和控件可读性；让素材、画布、时间轴、属性区可调节；清楚区分未保存草稿、未应用预览和待更新素材；窄屏改为按区域切换的布局。

## 约束

- 保持无前端构建步骤，不新增运行时服务或外部依赖。
- 不迁移、重建或整理现有 `assets/` 和工作区艺术素材。开发测试使用临时工程与合成图。
- 保持跨窗口配置与素材版本保护；缓存不得令旧页面覆盖外部修改。带版本号的图片可以缓存，配置与变更响应不能缓存。
- `processed_sprites/imports/` 和 `_approved/` 的手工素材必须受到保护。
- 每一阶段独立可用、单独验证，并拆成多个可回退的 Git 提交。性能阶段后允许停下供真实工程测试。

## 验收重点

- 相同图片 URL 重复打开无需重新传输；图片内容或版本变化后可看到新像素。
- 重复读取未变化工程不重复解码所有 processed 图片；文件变动仍刷新轮廓和素材版本。
- 预览保持原有帧身份、像素、无磁盘写入语义；快速切换不会用过期结果覆盖当前视图。
- 任何性能缓存都不能削弱路径限制、工程锁和冲突检查。
- 后续功能对磁盘写入失败、页面关闭、外部修改和大文件有明确行为。
