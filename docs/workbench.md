# 本地 Sprite 动作工作台

本文说明操作方式。Agent 制作、扩展或修复动作必须先遵循 [制作与验收流程](agent-sprite-workflow.md)，绑定正式 IDLE 基准、记录实际边界并完成验收；网页不会自动强制执行这些美术质量规则。

## 网页工作流程

工作台使用浅色面板与深色透明棋盘画布，顶部按「角色基准 → 切割 → 调整 → 动作 → 导出」组织。阶段切换保留当前草稿；原有版本恢复、工程设置和重新载入位于右上角「工程选项」。

- **角色基准**：新工程先进入此页。左侧导入、选择参考图，中间并排查看所选人设与当前 `idle` 动作首帧。当前首帧只是播放对照，不自动标记为已批准，也不取代 Agent 制作记录中的正式基准。此版本没有网页生成服务。
- **切割**：选择原图，使用自动识别、规则网格、整张单帧或手动区域。「选择 / 移动」可直接移动已有区域，八个边角手柄用于缩放；「新建区域」用于拖拽框选。方向键移动 1 px，Shift + 方向键移动 10 px；Esc 或指针取消会放弃当前拖动，一次完成的拖动只产生一次撤销记录。右侧也可编辑 X、Y、宽度、高度。手动编辑会转为矩形切割，保留所选帧 ID；自动连通域的像素掩膜不继续用于手动矩形。底部「保存当前切割」只保存这张原图的切割规则、帧身份和原始切片，其他动作、缩放等草稿保持未保存。
- **调整**：单帧微调与整组基准分开显示，可直接拖动画面调整单帧偏移。顶部「预览动作」可选择实际动作，并按「游戏播放」或「展示播放」使用对应顺序、重复帧和时长；跨原图的帧也会完整播放。点击时间轴中的帧会定位到其所属原图；同一素材的所有重复位置共用调整结果。没有动作时使用明确标记的「素材检查」，按工程默认 FPS 查看原帧。单帧值沿用旧工程的绝对覆盖语义。预览更新保留播放位置和已播放时长；「应用调整并保存工程」仅写入变化的 PNG，但仍保存整个草稿。动作页、Review 与导出使用已应用的素材。
- **动作**：在「动作编排」与「衔接检查」间切换。现有跨原图选帧、排序、运行时/展示节奏、Review 范围与重复次数继续可用。
- **导出**：顶部入口打开导出面板，保留原有动作资源、Review 和完整工程下载。

切割规则仍存于 version 2 的 `pipeline.json`，没有迁移既有工程。手动区域的 `boxes` 与 `region_ids` 一一对应；界面序号只表示当前顺序，素材 ID 不因移动、缩放或排序而变化。`identities` 记录区域来源，`next_id` 记录后续 ID 的分配起点，删除区域后不会自动回收旧 ID。已有工程按旧身份记录或区域匹配接入，自动重新识别后的区域需要人工复核。

原始切片保存到 `source_sprites/<原图>/`。调整预览和应用会核对原图、切割规则、切片校验和及身份记录，复用有效切片；只修改缩放、偏移或工程画布不会要求重新切原图。缓存缺失、损坏或失效时，预览会在内存中重新切割，不暗中写文件；点击「保存当前切割」可重新建立缓存。该目录仍是可重建缓存，不必纳入 Git 或工程导出。

保存切割不会删除现有 processed 图片。移除已被保存动作引用的区域会被阻止，即使网页动作草稿已移除引用也需要先保存动作；未保存的动作引用同样会在网页受到保护。带已保存单帧覆盖的区域也需先重置并保存。切割保存纳入版本恢复及配置/素材冲突检查，失败会回滚；保留的其他草稿可继续撤销或保存。

单帧处理使用有容量上限的服务内缓存：原始像素、画布、锚点、有效单帧设置及整组倍率共同决定结果是否可复用。已有预览后只改一个单帧覆盖，仅重新处理该帧，并只传回变化的图片；其他图片、时间轴节点与已保存 PNG 的修改时间保持不变。首次预览、缓存被淘汰或原图/切割/整组设置变化时，会重新处理受影响的帧。`fit_height` 仍按整组最高轮廓计算，不能把每帧独立拟合成同高。

应用调整会比较当前原图各帧的实际像素，只替换发生变化的 PNG，并保留对应的配置、处理清单及变化文件的恢复记录。保持版本冲突与失败回滚保护。预览中的草稿像素不会自动写入正式素材；独立导入的帧或无法对应原图切片的变体可参与动作播放，但调整控件会显示只读。

依据用户要求，第二轮只运行 Python 与 Node 自动化检查，不进行浏览器测试；网页体验与视觉验收由用户完成。

CLI 与网页共用独立切割操作：

```powershell
python tools/projects.py save-slices <工程ID> --source idle.png
# 可提供仅包含 extract 设置的 JSON，并附加 --revision / --asset-revision
python tools/projects.py save-slices <工程ID> --source idle.png --extract cuts.json
```

需要复现浏览器交互检查时，在装有 Playwright 和 Chromium 的环境运行 `python tests/browser_slicing_smoke.py`。它仅使用临时工程和合成图片，截图写入 `.playwright-mcp/slicing-loop/`。

## 启动

Python 3.10+，在仓库根目录运行：

```powershell
python -m pip install -r tools/requirements-workbench.txt
python tools/serve_sprites.py
```

默认打开 `http://127.0.0.1:8765` 的工程列表，服务仅监听本机。支持新建、打开和切换 `workspaces/` 下的工程；可用 `--workspace-root` 指定工作区根目录、`--config` 直接打开已有工程（包括旧布局）、`--port` 指定端口、`--no-browser` 禁止自动打开浏览器。关闭服务终端即可停止。

新建工程时设置名称、目录名、画布大小和归一化锚点。目录名留空则使用名称，支持中文。新工程可以没有原图和动作，也可以仅导入 processed 单帧。工作台不会自动迁移 `assets/`。目录和 CLI 约定见 [工作区说明](../workspaces/README.md)。

打开工程后可在“工程设置”修改展示名称、画布尺寸和锚点。这些修改先进入可撤销草稿；保存工程只写参数，不自动缩放或覆盖已处理图片。改变画布或锚点后，原图处理结果会标记待更新，需要逐张重新应用。`imports/` 和 `_approved/` 的手工素材不会自动改变；画布尺寸变化时应按新画布重新制作或导入，之后再导出资源。

首次打开会读取现有 processed 和动作。没有 processed 时，可以“准备缺失素材”，只生成尚未存在的原图处理目录。已有目录不会被这个操作重建。

## 编辑与保存

工程仍为 version 2 的 `pipeline.json`，既有字段、额外元数据和路径映射会保留。Review 是额外的 `workbench.reviews` 字段，CLI 会忽略它。

| 操作 | 配置 | processed | 其他输出目录 |
| --- | --- | --- | --- |
| 参数预览、动作播放、时间轴编辑 | 仅网页草稿 | 不变 | 不变 |
| 保存工程 / Ctrl+S | 保存当前草稿 | 不变 | 不变 |
| 保存当前切割 | 仅保存当前原图的 extract | 不变 | 更新对应 source_sprites 缓存 |
| 应用处理并保存工程 | 保存整个草稿 | 仅替换所选原图中像素变化的帧 | 不变 |
| 准备缺失素材 | 保存整个草稿 | 仅补充缺失原图 | 不变 |
| 导入图片 / 保留已有最终帧 | 保存整个草稿 | 添加素材 | 不变 |
| 导出 | 不变 | 只读 | 临时生成 ZIP 下载 |

更改处理参数后，动作预览仍使用已经应用的 processed 图片。参数预览并未提交为素材；确认后点击“应用处理”。仅保存规则不会自动重算图片。已由工作台处理的原图会在规则或源图改变后显示“待更新”。

编辑区上方分别显示“工程”“处理预览”“素材”的状态。“草稿待保存”只表示配置还在网页中；“预览待应用”表示处理参数尚未写入 processed 图片；“素材待更新”表示已保存的规则或原图与现有 processed 图片不一致。保存工程后会刷新素材状态，但不会自动重建图片。

桌面界面可拖动素材区与画布、画布与属性区之间的分隔条，也可聚焦分隔条后使用方向键调整；画布下方的分隔条调整时间轴高度。尺寸会保存在当前浏览器中，不改动工程配置。

窄屏会显示“素材 / 画布与时间轴 / 属性”切换按钮，每次只展示一个工作区域。选择原图、动作或参考图后会打开画布；“素材处理 / 动作编排 / 衔接 Review / 参考图”的工作模式仍可独立切换。素材列表和属性区各自滚动，短横屏会收紧顶部栏，把更多高度留给编辑区。

编辑操作支持撤销 / 重做，草稿历史保留在本次网页会话中。保存切割、应用、准备、导入、迁移和删除会另存受影响文件的上一版本；点击“版本记录”可恢复。恢复前会检查当前配置、素材版本和相关文件，拒绝覆盖操作之后的外部修改。恢复本身也留下可再次恢复的版本。版本保存在工程的 `.sprite-workbench-history/`，不随普通资源导出或完整工程 ZIP 携带，使用时间久后会占用磁盘空间。旧布局若将待修改文件放在工程目录外，应先手动导出完整工程备份。关闭网页前仍会提醒未保存草稿。

CLI 使用 `python tools/projects.py history <工程 ID>` 查看版本，再用 `python tools/projects.py restore <工程 ID> <版本 ID>` 恢复；可附上 `--revision` 和 `--asset-revision`，按先前读取的版本号拒绝过期提交。

保存使用工程文件摘要做冲突检查。其他窗口或 CLI 改变配置后，旧窗口不能直接覆盖它；有未保存草稿时可点击“合并配置”。网页会自动合并双方修改的不同字段，双方都修改的字段逐项选择当前草稿或磁盘版本。动作帧数组作为一个字段处理，不按位置悄悄拼接。合并结果仍是未保存草稿，检查后再保存；若此时磁盘又变化，保存仍会被拒绝。也可下载配置草稿后自行合并。

工作台在页面可见时每 12 秒、以及返回窗口时检查外部修改。没有未保存编辑时自动更新；有草稿时显示提示并保留草稿。仅图片变化可点击“刷新”更新素材而保留配置；配置也变化时，可先“下载配置草稿”，再重新载入并合并。切换工程会提醒未保存修改。

网页、`projects.py` 和分阶段 CLI 共用工程级跨进程锁。素材写入同时检查素材版本，避免旧页面覆盖 Agent 更新的图片。手工直接写文件不受锁控制，建议先写临时文件再替换，并让网页刷新后再继续处理。

## 素材处理

1. 点击“素材处理”，选择原图；左上角 ＋ 可导入原图。
2. 选择自动连通域、规则网格、手动区域或整张单帧。连通域适合透明角色图，网格适合严格排布的图集。
3. 在“原图 / 切图”中拖出矩形可切换到手动框选。切图区域及高级参数也可通过 JSON 调整。连通域还会将分离的小特效归属到邻近主体；框选则保留矩形内的完整像素。
4. 调整整组缩放、目标高度、位置、画布内限制和越界策略。`fit_height` 按整组最高轮廓计算共享倍率，不把每一帧拉成同样高度。
5. 时间轴选择某帧，在“处理结果”画布中直接拖动图片调整位置，所选帧的水平、垂直偏移同步变化；也可继续输入数值或设置绝对缩放覆盖。开启“前帧叠图”或“Idle 参考”可对照固定位置反复微调。拖动按画布像素换算，松手后自动刷新处理预览，不保存工程或更新 processed；一次拖动是一次可撤销操作，Esc 取消当前拖动。松手后的预览仍遵循当前画布限制、越界等处理规则，原样复制模式不支持偏移。清空“目标高度”可停用自动高度适配；单帧缩放留空则继承整组倍率。
6. 检查结果后应用。共享该素材的所有动作随之更新。

项目使用 `pipeline.json` 中统一的 `frame_size` 和 `anchor`。工作台显示固定地面线与锚点，不逐帧自动调整显示大小。导入 processed 单帧需与工程画布一致。

固定画布和 `fit_height` 不保证跨原图的角色本体同尺度。抬手、道具和特效会影响整体轮廓，轮廓底边也不一定是脚底；必须对照 IDLE 的本体比例和接地点检查，保留蹲伏、离地等合理动作变化。Agent 新修图先导入 source，再处理；直接导入 processed 仅用于历史兼容。

素材编号按区域匹配保留：相同框优先，其次是不歧义的高重叠区域。新区域分配新的编号。应用后将 ID 与原图区域的对应关系保存在 `extract.identities` 中，因此清理切图缓存、重开工程或用 CLI 重建时也可恢复相同 ID。自动匹配不能替代人工确认；切图发生较大变化时，应检查每帧身份。若仍有动作引用被移除区域，会阻止应用，请先调整引用。切图删除的帧若仍有处理覆盖，也需在“处理规则 JSON”中移除相应覆盖。

## 动作编排

原图、processed 和参考图的文件选择器均支持多选。图片逐张提交，界面显示进度；某张图片无效或重名时会报告失败并继续处理其他图片，已成功导入的图片会保留。发生版本冲突或会话失效时停止队列，提示剩余未处理数量。每张图片最大 40 MiB。

素材库勾选“多选”，或直接 Ctrl / Shift 点击素材，可选择多张；Shift 支持按当前筛选顺序连选。“全选当前结果”只选择搜索和来源筛选后的素材，“清空”清除选择。“加入动作”按素材库顺序批量添加，作为一次可撤销操作，游戏播放模式下可用。

“删除”会删除已选择的 processed 文件；原图列表上方的“删除原图”同时清理对应切片缓存、processed 和该原图规则。删除会保存当前草稿，不能通过网页撤销。若任一待删素材仍被动作使用，整批删除会被阻止并列出动作名称；请先移除或替换引用。删除自动生成的单帧不改变原图切图规则，以后重新应用原图可能再次生成它。文件或配置写入失败时，删除操作会恢复此前移走的文件和元数据。

- 点击 ＋ 创建动作，ID 使用字母、数字、下划线或短横线。
- 在动作库选择动作后，点击列表上方“删除动作”。仍被 Review 引用的动作会被阻止删除，并列出相关序列；先移除对应片段或删除这些序列。确认删除后支持撤销 / 重做，保存工程后写入配置，素材图片保留。
- 点击素材或拖入时间轴，支持跨原图取帧及多次使用同一张素材。
- 拖拽排序，支持重复、倒序、删除。动作只存引用，实际 PNG 不会复制一份。
- “游戏播放”按素材顺序和动作 FPS 播放；图集和元数据使用此顺序。
- “展示播放”支持独立排序、重复、逐步停留时长，以及 WebP 循环次数。0 次表示无限循环。
- 调整游戏帧槽位时，会保留已有展示顺序与时长的对应关系；可用“恢复为游戏播放”清空展示覆盖。
- “定位到素材处理”可回到原图处理页。独立导入或已确认素材没有可自动重建的原图对应关系。

播放 / 暂停为 Space，左右方向键单步，Delete 删除选中游戏帧，Ctrl+Z / Ctrl+Shift+Z 撤销 / 重做。预览循环和播放倍速仅影响当前查看，不改写游戏或 WebP 参数。

## 衔接 Review

可保存多个序列，每个片段设置动作、重复次数、起始步和结束步（0 起，结束包含在内，空值表示播放到末尾）。Review 可选择游戏或展示播放参数。

选择 Review 后，点击列表上方“删除序列”可删除该序列。删除前会确认名称，动作和素材图片保留。删除先进入可撤销草稿，保存工程后写入配置；属性检查器中的删除按钮使用相同规则。动作和 Review 都可删除至空列表。

例如 `idle × 2 → attack × 1 → idle × 2`、`jump → land → idle`。首次打开大肥鱼工程会生成这两个建议序列作为未保存草稿，保存后才写入配置。

点击片段，再使用“衔接前一帧”和“片段第一帧”，配合前帧叠图、Idle 参考、固定画布、慢放，检查大小及姿势变化。此处直接切帧，不添加会掩盖问题的插值或淡化。

“Idle 参考”叠图固定使用 `actions.idle.sprites[0]`，不自动绑定 `references/` 中的正式基准；Agent 应核对两者是否对应。

验收使用游戏播放（`runtime`）。局部接缝 Review 必须与完整动作采用相同的真实出口 / 入口槽位、边界去重、重复和时长；跨动作 Review 无法表达节奏调整时，用最终动作的对应范围检查。每处过渡的两端都要覆盖，随后以正常速度、慢放和逐帧检查整段。仅保存 Review 或导出动画不算完成检查；记录所用版本、实际查看结果及待办。完整要求和记录模板见 [制作与验收流程](agent-sprite-workflow.md)。

每个片段最多重复 100 次，一个序列最多 10,000 步。缩短动作后，网页会把现有 Review 的越界范围限制在新的有效范围内。Review 导出包含 WebP 及逐步来源和时长记录，即使编码器合并相同连续画面，也可追溯原始编排。

## 参考图

“参考图”页签支持批量导入、原尺寸查看和删除参考图片。新图片保存于工程的 `references/`，不加入 source 扫描、processed 素材库或动作。已有 `reference/` 中的图片也可查看和删除，原目录不自动迁移。完整工程备份会同时保留两种目录中的资料，包括图片以外的说明和提示词。

## 迁移手工最终帧

在开始重新编排前，点击“保留已有最终帧”：

1. 读取现有最终帧的编号顺序。
2. 与动作中相应位置引用的 processed 比较像素。
3. 不同或缺失的帧复制到 `processed_sprites/_approved/<action>/`。
4. 按已有最终帧重新建立该动作的素材引用，并保存。

这个操作保留了人工修图，但也会以已有最终帧为准恢复该动作的顺序和帧数，因此应在开始新编排前使用。原来的 `frames/` 不删除、不覆盖。若历史最终帧和当前展示 / Review 范围不兼容，会报错并保留旧工程，请先调整配置。

## 导出与备份

- **PNG 帧序列**：按游戏顺序编号的单帧 ZIP。
- **图集**：PNG、TexturePacker Hash JSON、动作元数据和 manifest。
- **WebP**：按展示顺序、逐步时长和展示循环编码，并附播放记录。
- **GIF**：同样使用展示顺序和循环设置，适合在系统播放器中查看；ZIP 内的 `gif/` 目录包含 GIF 与逐步播放记录。GIF 每帧最多 256 色，透明度只有透明或不透明，时长按 10 ms 取整且至少 20 ms，画质以 WebP 为准。
- **完整动作资源**：包含上述四类，可选择一个或多个动作。
- **Review**：当前 Review 的 WebP、GIF 与播放记录。
- **完整工程**：原图、processed PNG / 阶段描述、工程 JSON、`references/`（及已有 `reference/`）和工程 `README.md`。路径统一为相对路径，解压到 `workspaces/<目录名>/` 即可在列表中打开，也可以通过 `--config` 打开。切图缓存和交付目录不包含在备份中。

Agent 可用 `python tools/projects.py qa <工程> --action <动作> --output <新目录>` 从已应用的 processed 帧一次生成 WebP、GIF、逐槽位对照图和时序报告；也支持 `--review <已有Review>` 或重复 `--ref <processed引用>`。这个只读命令适合取代大量逐帧浏览器截图，实际视觉验收仍需观看动画与关键接缝。
特殊节奏可用 `--sequence <JSON文件>` 提供有序的 `steps`（每步 `ref`、`duration_ms`）和 `loop`，直接生成同样的证据，不必改动工程动作。

其他导出类型用于交付游戏资源；需要重新打开整个编辑工程时，请选择“完整工程”。所有导出都基于当前动作草稿和已应用的图片，不要求先保存配置，也不写入项目的 `frames/`、`sheets/` 或 `previews/`。

网页导出会显示当前处理阶段与已完成项目数。“取消生成”会在当前文件或动作编码结束后的安全边界停止任务；取消或失败的任务不提供不完整 ZIP。导出任务保存在本次服务进程内，重启本地服务后需重新生成。

“准备缺失素材”也会显示处理进度和当前原图。点击“取消准备”后，会在当前原图处理结束时停止；写入工程前取消不会生成部分 processed 图片。进入最终写入阶段后，操作会完成并显示结果。

`source_sprites/`、临时文件、锁和工作区工程的 `exports/` 被 Git 忽略。processed 全部默认保留，其中 `_approved/` 和 `imports/` 尤其不能按缓存清理。
