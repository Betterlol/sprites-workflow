# Agent Sprite 制作与验收流程

本流程适用于新建、扩展和修复角色动画。Agent 必须按顺序完成基准确认、子动作规划、整张 spritesheet 生成、处理、衔接检查和完整动作验收。不得仅凭生成成功、配置合法或 WebP 能播放就宣布完成。

目录与协作规则见 [工作区说明](../workspaces/README.md)，操作见 [工作台说明](workbench.md)，配置见 [流水线说明](sprite-workflow.md)，任务与生成提示词见 [示例](prompt-sample.md)。本流程是制作规范；其中的制作记录不是新增的 `pipeline.json` 字段，也不是工作台已经实现的自动质量检查。

## 1. 开始前读取现状

1. 依次读取根目录 `AGENTS.md`、`workspaces/README.md`、本流程、目标工程 `README.md` 和 `pipeline.json`；用 `python tools/projects.py status <project-id>` 获取当前配置、版本、素材和警告。
2. 以磁盘中的实际引用核对工程说明。说明过期、来源记录不存在或基准不明确时，先记录差异，不根据旧动作名、文件编号或历史导出来猜当前状态。
3. 草稿、提示词、参考帧副本、候选图和 Review 证据放在 `_work/<task>/`。不把它们导入 `references/`、`source/` 或 `processed_sprites/`。
4. 将本次范围、已确认基准、动作拆分和验收记录写入工程 `README.md` 的“制作记录”，可使用文末模板。沿用已有确认和任务授权，无须为每个子动作重复请求确认；不能把未检查的候选标为已批准。

现有 `assets/` 和无关工程不在任务范围内。文档审阅或文档修改任务不得顺带修改素材、动作配置或重新处理图片。

## 2. 绑定唯一的 IDLE 基准

在生成后续动作前，记录并实际打开查看以下内容：

| 项目 | 必须明确的内容 |
| --- | --- |
| 形象基准 | 已确认的 IDLE key pose 的精确路径、版本或文件摘要；必要时附用户原始人设参考 |
| 来源与播放基准 | 对应的 source 原图及区域、processed 引用；仅作形象参考而不参与播放时明确注明 |
| 固定约束 | 朝向、身体与头部比例、主要颜色、线条与明暗风格、角色本体的视觉尺度 |
| 空间基准 | 工程画布、锚点、站立接地点与角色本体定位标志；已有容差也要记录 |
| 动作允许变化 | 蹲伏、跃起、转头、表情及合法道具状态等，不能为了像 IDLE 而抹掉动作变化 |

`references/` 只保留用户参考、一个已确认的 IDLE 基准和必要的正式记录。若该 IDLE 同时作为可玩素材，已采纳的原始画面也必须先导入 `source/`。单张 IDLE key pose 可以用于约束形象；动画 IDLE 仍须由完整 spritesheet 制作。

后续每次生成都必须实际提供 IDLE 图片，不能只在提示词中写它的文件名。IDLE 约束角色身份、比例、风格和视觉尺度；前后边界帧约束当前姿态、表情、接触关系与道具状态，两类参考必须同时满足。已经有批准的基准时不得自行换用新的候选；无法确定既有基准时先做不依赖它的规划，明确待确认项，不批量生成正式后续动作。

工作台的“Idle 参考”叠图目前取 `actions.idle.sprites[0]`，不会自动绑定 `references/` 中的基准。Agent 必须核对两者是否对应；不对应时另行打开正式基准作比较，不能默认为已经检查。

## 3. 先规划子动作与实际播放边界

长动作按语义拆分，例如 `取碗 → 第一口 → 最后一口 → 收碗`。每个子动作有自己的原画 spritesheet，能独立播放；完整动作复用同一批 processed 引用。过渡也作为可单独播放、检查的子动作保存。

生成前为每段记录：动作 ID、语义、入口姿态、出口姿态、道具与表情状态、目标运行 FPS、预计时长和循环方式。统一完整动作的运行 FPS；若子动作使用不同 FPS，必须明确转换后的帧重复和时长，并以转换后的序列验收。

边界始终取自最终采用的运行时序列或明确记录的片段范围：

- 记录前段动作 ID、实际出口槽位及 processed 引用，以及后段动作 ID、实际入口槽位及 processed 引用。槽位从 0 开始；重复引用也占独立的播放槽位。
- 原图最后一格、processed 文件名最大的编号和展示 WebP 最后一帧，都不能代替实际运行时出口。
- IDLE 的形象基准与本次播放出口是两个概念。明确从 IDLE 的哪一个槽位离开、回到哪一个槽位；接缝 Review、完整 Review 与最终动作必须使用相同边界。
- 对允许从多个 IDLE 相位进入或被其他动作中断的需求，记录允许的入口范围并分别检查；只检查一个 key pose 不能证明任意时刻切换都自然。

## 4. 选择衔接方式并生成整张原画

### 4.1 共享边界直接衔接

新制作的后段 spritesheet 以前段已采用的末帧 `E` 为起点约束。实际提供 `E` 的图片，并要求首姿态匹配。切图、处理后检查匹配程度；生成模型画出的相似首帧不自动等于原来的 `E`。

若后段独立动作为 `[E, B1, B2]`，前段为 `[A0, A1, E]`，完整动作可使用：

```text
前段全部 + 后段从槽位 1 开始 = A0, A1, E, B1, B2
```

在制作记录中写清后段用于完整动作的范围。只有确认姿态共享且运动方向、速度与状态连续时，才能直接衔接；否则进入过渡生成。边界默认只播放一次，有意停顿要记录实际时长与原因。

### 4.2 用双端点生成过渡

当前段出口 `E` 与后段实际入口 `S` 无法直接衔接时，用这两个已采用的原帧作为端点，生成一整张过渡 spritesheet：

```text
生成 sheet：E 的匹配姿态, T1, T2, …, S 的匹配姿态
过渡动作：T1, T2, …
完整动作：前段（含原 E） + 过渡动作 + 后段（含原 S）
```

同时提供 IDLE、`E` 和 `S` 的实际图片，并明确各自用途。前后段各取边界附近 2–3 个不同姿态作为运动上下文，检查移动方向、转动趋势、接触关系和节奏；只有一帧时如实记录。若后段 sheet 开头包含前段的共享姿态，先确定去重后的实际入口，再选择过渡端点。工具无法接受必要参考时，说明限制，不能声称已经完成双端约束。

提示词必须说明帧数或时长、阅读顺序、视角、角色尺度、地面基准、两端姿态、运动路径，以及道具持有、饭量或其他状态如何变化。要求中间动作渐进，不能在末帧突然换成目标姿态。

生成的端点用于核对约束，默认不选入过渡动作；完整序列保留原 `E`、原 `S`，避免重复播放或被重画的近似端点替换。切图后必须分别检查 `E → T1` 和 `T末 → S`；端点对齐但方向突变、速度突跳、道具瞬移仍判为失败。过渡失败时重新生成整张过渡 sheet，必要时调整拆分或时长，不用散落的单帧拼出过渡。

直接衔接与补过渡是同一接缝的两种处理方式，无须对已经自然连续的共享边界机械地再加过渡。不能把某次四格原画“只选中间两帧”的取舍推广为固定帧数规则。

### 4.3 单帧修复的范围

孤立帧生成仅用于修复明确的坏帧，例如手部结构错误、道具缺失或错误表情。记录被替换的引用和缺陷；将 IDLE、坏帧及相邻帧作为参考。采纳后把修复原图先导入 `source/`，处理并替换引用，再检查两侧和完整动作。缺少一段运动应生成过渡 spritesheet，不以“修复”名义逐张补齐。

## 5. 先采纳原画，再切图和处理

候选在 `_work/<task>/` 中检查，采纳的 spritesheet 或单帧修复原图通过 `python tools/projects.py import <project-id> --kind source --file <采用原画路径>` 导入，随后用 `python tools/projects.py apply <project-id> --source <原图文件名>` 切图和处理。实际路径含空格时加引号；配置修改与版本保护遵循工作区说明。复制的参考端点、缓存切片和 processed 输出不得回填 `source/`。`imports/`、`_approved/` 仅兼容历史素材。

处理时遵守以下约束：

- 使用固定画布并对照 IDLE 的角色本体尺度、头身比例和定位标志。不能按每帧总包围盒把蹲伏、抬手等姿势都拉成同高。
- `fit_height` 按每张原图内最高的完整轮廓计算共享倍率，不会跨 sheet 自动校准；道具、头饰和特效可能改变高度。必须跨 sheet 检查，必要时显式设置整组 `scale` 和 `offset`。
- `anchor` 模式对齐整体透明轮廓的底边与水平中心，底边不一定是脚底，中心也不一定是身体中心。道具伸出、悬空、跳跃或离地特效应按角色本体校正，不能把所有帧强行压到地面。
- 单帧覆盖仅用于有依据的校正，记录原因并检查是否造成缩放抖动。姿态、结构或运动本身错误时回到原画返工。
- “保存工程”只保存参数；验收使用已应用的 processed。参数或原图待更新时，不能把旧处理结果当成新结果验收。

同一素材改动会影响所有引用它的动作。不得通过重命名或重编号素材调整动作顺序；替换前记录受影响的子动作、接缝和完整动作，旧成果按项目约定归档后再退出活动使用。

## 6. 从同一份编排得到完整动作与 Review

在制作记录中列出完整动作的有序组成：每段动作 ID、选用的运行时槽位范围、重复次数、共享边界去重和有意停顿。按这份组成展开引用与时长，再与完整动作逐项比较。

必须检查帧引用顺序、总槽位数、逐步时长和总时长。差异必须是记录过的去重、节奏或范围选择；不能在完整动作中默默删掉一段过渡，而仍拿包含它的子动作 Review 当验收依据。完整动作不会自动跟随子动作更新，不能因为引用相同目录就假定两者一致。

Review 至少包含：

1. 每个子动作单独播放；循环动作检查自身首尾。
2. 每处接缝的 `前段尾部 → 过渡（如有） → 后段头部`，同时覆盖过渡的两端。
3. 按记录范围组成的完整子动作序列，以及 `前置动作 → 最终完整动作 → 后置动作`。需要回到 IDLE 时检查真实返回槽位；死亡等终止动作按需求检查最终状态。

Review 使用 `runtime` 参数作为游戏动作验收依据。局部和全段必须使用相同的实际边界、去重、帧重复与播放时长。若跨动作 Review 无法准确表达完整动作中的节奏调整，以最终动作的对应范围建立接缝 Review；展示 WebP 的 `animation.order` 或慢放不能代替运行时检查。

局部 Review 为便于观察而循环时，区分末尾回到开头的查看循环与实际游戏接缝，只验收需求中真实发生的切换。导出游戏帧、图集与元数据后按运行时序列核对；展示 WebP 允许独立编排，但须注明并另行核对，不能用展示编排证明游戏动作通过。

## 7. 验收、返工与完成条件

每个子动作、每处接缝和完整动作都必须以正常运行速度、慢放和逐帧方式检查。使用固定画布、地面线、前帧叠图和正式 IDLE 对照，不添加插值或淡化掩盖问题。

| 检查项 | 通过条件 |
| --- | --- |
| 角色一致性 | 身份、比例、画风、配色和本体尺度一致；动作变形有依据，无无意放大缩小 |
| 地面与运动 | 接地点、重心、位移轨迹符合动作；无非预期滑动、上下跳动、反向抽动或瞬移 |
| 运动节奏 | 边界前后方向和速度合理；无遗漏动作、无意卡顿、突跳或多余反跳 |
| 表情与道具 | 表情变化有过渡；持握、左右手、遮挡、道具数量及内容状态连续 |
| 边界与编排 | 两端接缝通过；共享姿态去重正确，有意停顿已记录；Review 与最终序列一致 |
| 数据与交付 | 引用存在、配置合法、处理结果与当前原图及参数一致；游戏导出与运行时验收序列一致，独立展示编排另行核对 |

容差由工程约束决定；未规定的容差应在制作记录中写明本次采用的标准和检查依据，不能虚构工具已有自动判定。配置 `validate` 和软件测试只证明相应的数据或程序检查通过，不证明动作自然。

失败时按原因返工：对齐问题修正处理参数，坏帧按单帧修复流程，缺少运动或接缝不自然重做整张过渡，编排问题修正范围与时长并同步 Review。不得通过降低 FPS、无依据重复帧或跳过问题片段来掩盖缺陷。

修改基准、原画、处理参数、选帧、FPS、重复或范围后，对应验收结论失效；重新检查受影响的子动作、两侧接缝和完整动作。记录验收所用的配置 revision、素材版本或关键文件摘要，实际查看的证据路径、结果和剩余问题。仅创建 Review、导出 WebP 或列出检查清单不算完成检查。

只有全部适用检查通过且制作记录与实际配置一致，才可宣布完成。无法查看动画、缺少必要参考或仍有未解决问题时，明确标为“待验收”或“未完成”，说明已检查范围，不写“流畅自然、已完成”。

## 8. 工程制作记录模板

以下模板写入目标工程 `README.md`，用实际路径和槽位替换占位内容；已有记录可沿用相同信息，不必更换格式。详细提示词、候选及播放证据放 `_work/<task>/`；最终取舍、来源和验收结论必须保留在工程说明中，避免依赖会被清理的工作文件。完整工程备份包含工程 README；若另存正式记录，应放在会随备份保留的 `references/` 中并核对链接。

```markdown
## 制作记录：<任务 / 版本>

- 范围与依据：<用户要求；沿用的已确认结果>
- IDLE：<参考路径及摘要>；来源 <source/文件及区域>；播放参考 <processed 引用或不参与播放>
- 固定约束：<朝向、比例、配色、本体尺度、画布、锚点、接地点和容差>
- 运行参数：<FPS、时长、循环、允许的入口 / 中断范围>
- 子动作顺序：<动作 ID、语义、入口 / 出口状态、source 原图>
- 完整动作组成：<各动作运行时槽位范围、重复、去重、有意停顿及其原因>

| 接缝 | 前段实际出口：动作 / 槽位 / 引用 | 后段实际入口：动作 / 槽位 / 引用 | 方式与采用的过渡帧 | 道具、表情与运动约束 |
| --- | --- | --- | --- | --- |
| <编号> | <精确位置> | <精确位置> | <直接共享或过渡 source、processed 引用> | <状态和运动趋势> |

- 生成依据：<实际提供的 IDLE、端点、邻帧路径；提示词记录；采纳与舍弃原因>
- 编排核对：<完整动作与组成的引用、槽位数、逐步时长及总时长对比结果>
- 验收版本：<配置 revision、素材版本或文件摘要>
- 验收证据：<子动作、逐处接缝、完整动作的 Review ID、实际边界与证据路径>
- 视觉检查：<正常速度 / 慢放 / 逐帧的实际结果、检查者>
- 返工与状态：<已解决问题、待办；通过 / 待验收 / 未完成>
```
